AUTOREGRESSIVE-DECODING(7)  Transformer 生成机制        AUTOREGRESSIVE-DECODING(7)

名称
       autoregressive-decoding — 将序列生成分解为逐 token 条件预测的
                                串行解码范式

概述
       自回归解码是一切 LLM 文本生成的基础范式。它利用概率链式法则
       将序列的联合分布逐步分解，每一步基于所有历史 token 预测下一个
       token。该机制决定了推理必然是串行迭代的过程，并直接催生了
       KV 缓存、批处理调度等上层技术。

描述
       本手册沿问题链剖析自回归解码的数学根基、执行机制、计算瓶颈
       及与 KV 缓存的衔接。

       问题 0 · 模型如何定义“序列”的概率并据此生成？
       │
       ├── 联合概率的分解：
       │       给定 token 序列 x = (x₁, x₂, ..., x_T)，
       │       自回归模型将其联合概率分解为条件概率的连乘：
       │           P(x) = Π_{t=1}^T P(x_t | x_{<t})
       │       其中 x_{<t} 表示前 t-1 个 token。
       │       每个条件项由同一个网络（如 Transformer）参数化。
       │
       ├── 生成策略：
       │   从初始 token（如 <bos>）开始，反复执行：
       │       1. 将当前序列 x_{<t} 输入模型，得到 logits。
       │       2. 将 logits 经 Softmax 转为概率分布 P(x_t | x_{<t})。
       │       3. 从该分布中采样（或贪心选择）下一个 token x_t。
       │       4. 拼接 x_t 到序列尾部，作为下一步的输入。
       │
       └── 该过程天然串行：第 t 步的输出依赖第 t-1 步的结果，
           因此无法直接并行生成整个序列。
           引出：如何在保证正确性的前提下加速每一步？

       问题 1 · 每一步的前向计算如何避免重复处理历史？
       │
       ├── 计算瓶颈：
       │   Transformer 的注意力需要查询 token 与所有历史 token 的
       │   Key 和 Value 进行交互。若无优化，第 t 步需为所有前 t 个
       │   位置重新投影 K 和 V，计算量 ∝ t·d²。
       │
       ├── 解决方案：KV 缓存（见 kv-cache(7)）
       │   - 保存每层每个历史 token 的 K 和 V 张量。
       │   - 第 t 步仅计算新 token 的投影 q_t, k_t, v_t。
       │   - 注意力计算时，从缓存中读取 K_{<t}, V_{<t}，拼接 k_t, v_t。
       │   - 计算量降为：常数 d²（投影） + O(t·d)（注意力点积），
       │     彻底消除了重复投影开销。
       │
       └── KV 缓存使自回归解码在计算上可行，但存储开销随序列
           长度线性增长，引发显存瓶颈，进而推动了分页、量化等优化。

       问题 2 · 解码策略如何影响生成质量与效率？
       │
       ├── 贪心解码（Greedy）：直接选取概率最大的 token。
       │   - 确定性，速度快，但易陷入重复循环。
       │
       ├── 温度采样（Temperature Sampling）：
       │   - 调整 Softmax 的平滑度： P(x_t) ∝ exp(logits / τ)
       │   - τ→0 趋近贪心；τ>1 增加多样性；τ<1 更尖锐。
       │
       ├── Top‑k 与 Top‑p（Nucleus）采样：
       │   - 截断低概率 token，避免噪声，平衡多样性与质量。
       │
       ├── 束搜索（Beam Search）：
       │   - 同时维护 k 个最优候选序列，每步扩展后保留 k 个最优。
       │   - 提升整体序列概率，但计算量扩至 k 倍，且多样性受损。
       │
       └── 这些策略均在自回归框架内，仅改变从 logits 到 token 的
           选择逻辑，不影响底层迭代和 KV 缓存机制。

       问题 3 · 自回归解码的迭代本质如何影响系统设计？
       │
       ├── 单次迭代不可分割：
       │       一次模型前向只能生成一个 token（decode），
       │       或并行处理一批 prompt token（prefill，见 prefill(7)）。
       │       这定义了迭代粒度为“一次 forward”。
       │
       ├── 迭代级调度诞生：
       │       由于不同请求的步数不同，必须在每次迭代边界重组 batch，
       │       催生了 Continuous Batching（continuous-batching(7)）。
       │
       ├── 内存管理必须伴随迭代：
       │       每步追加 1 token 的 K/V，页式管理在迭代结束时更新
       │       引用计数，满足动态分配与回收（pageattention(7)）。
       │
       └── 总结：自回归解码的串行性不是缺陷，而是一种结构约束，
           它统一了推理系统的计算、内存与调度设计空间。

结论
       自回归解码将序列生成规约为重复迭代的条件预测，KV 缓存使
       每次迭代的计算量恒定，而迭代本身则成为更高层调度与内存
       管理的统一节拍。理解这一机制是掌握所有 LLM 推理优化技术的
       起点。
