# VLLM(7)                     Miscellaneous Information                    VLLM(7)

## NAME

**vLLM** — 高吞吐量、低延迟的大语言模型推理引擎，核心技术为 **PagedAttention**，灵感源于操作系统虚拟内存分页。

## DESCRIPTION

vLLM 通过将 KV Cache 管理抽象为分页系统，解决大模型推理中内存碎片、共享冗余、抢占调度和静态批次等瓶颈。以下采用 **问题 → 子概念 → 解决 → 新问题** 的链条逐层推导，使用树状缩进与简洁公式呈现核心机理。

---

### 第一层：KV Cache 的内存困境

- **自回归生成**：每步产生一个新 token，需基于所有历史 token 的 Key、Value 向量计算注意力。

  - 朴素方法：每步重算所有历史 $K,V$ → 计算量 $O(n^2)$，不可接受。
  - **KV Cache**：将每层每头已算出的 $K, V$ 缓存，后续步只做新 token 的 $Q$ 与缓存的 $K,V$ 运算，避免重算。

    - 单 token 的缓存大小公式（FP16 精度）：

$$
S_{\text{token}} = 2 \times n_{\text{heads}} \times d_{\text{head}} \times \text{sizeof(fp16)} \times 2 = 4\,n_h d_h\; \text{字节}
$$

总序列缓存：

$$
M = 4\, N\, n_h\, d_h\, L
$$

其中 $N$=层数，$n_h$=头数，$d_h$=头维度，$L$=序列长度。
    - 示例：LLaMA‑13B ($N$=40, $n_h$=40, $d_h$=128) ，$L$=2048 时，单个请求缓存约 $4 \times 40 \times 40 \times 128 \times 2048 \approx 1.6\,\text{GB}$。
- **问题：预分配导致的内部碎片**

  - 传统推理框架（如 FasterTransformer）为每个请求按 **最大长度** $L_{\text{max}}$ 预留 **连续显存**。
  - 实际生成长度往往远小于 $L_{\text{max}}$，未用空间既不能回收也不能分给其他请求。
  - 类比：操作系统的 **固定分区分配** → 产生严重 **内部碎片**，内存利用率极低。
  - 另外，连续分配要求大块空闲内存，时间一长也会出现 **外部碎片**。

---

### 第二层：PagedAttention — KV Cache 分页

**子概念**：将虚拟内存分页思想移植到 KV Cache 管理。

- **KV 块（Block）**

  - 把每个序列的 KV Cache 划分成固定大小的 **逻辑块**，每块包含 $B$ 个 token 的 $K,V$ （典型 $B = 16$）。
  - 物理显存划分为由 **物理块** 组成的 **块池**，所有请求共享。
- **页表（Block Table）**

  - 每个序列维护一张 **页表**，记录 逻辑块序号 $\to$ 物理块索引 的映射：

$$
\text{block\_table}[i] = j \quad\text{物理块 } j \text{ 存有该序列第 } i \text{块 KV}
$$
- **分页注意力计算**

  - vLLM 实现专用 CUDA kernel，遍历页表，对每个逻辑块取出物理块 $K,V$，与查询 $Q$ 交互。
  - 类似 **FlashAttention** 的分块数值稳定合并：  
对每块 $i$ 计算局部 softmax $(m_i, l_i)$，再依次合并得到最终输出 $o$。

$$
\begin{aligned}
m_{\text{new}} &= \max(m_{\text{old}}, m_i) \\
l_{\text{new}} &= l_{\text{old}} e^{m_{\text{old}}-m_{\text{new}}} + l_i e^{m_i-m_{\text{new}}} \\
o_{\text{new}} &= \frac{l_{\text{old}} e^{m_{\text{old}}-m_{\text{new}}} o_{\text{old}} + l_i e^{m_i-m_{\text{new}}} o_i}{l_{\text{new}}}
\end{aligned}
$$
  - 只需在 kernel 内完成块遍历，合并开销被计算掩盖。
- **效果**

  - 按需分配物理块，序列占用的块数 $= \lceil L / B \rceil$，**彻底消除内部碎片**。
  - 非连续物理块避免外部碎片，内存利用率接近 $100\%$。
- **命名**：

  - **PagedAttention** = Paged Attention（分页注意力）。
  - **vLLM** 中的 “v” 代表 virtual，强调类比 **虚拟内存**，实现 LLM 服务的内存虚拟化。

> **→ 逻辑块与物理块的解耦，使得多个序列的页表可以映射到同一物理块——前缀共享成为可能。**

### 第三层：前缀共享 — 消除冗余

- **新问题：多序列重复存储前缀**

  - 并行采样（同一 prompt 生成多个补全）、波束搜索、基于示例的少样本提示，均存在大量 **共享前缀**。
  - 若每个序列独立存储前缀 KV Cache，显存浪费将随并发数倍数增长。
- **子概念：块引用计数与共享**

  - 物理块内部维护 **引用计数** `ref_cnt`。
  - 多个序列的页表条目指向同一物理块 → `ref_cnt++`。
  - 共享前缀块 **只读**：序列生成新 token 时只需 **分配新物理块** 追加到页表末尾，原共享块不会被修改。
  - 序列结束时，遍历页表，每个物理块 `ref_cnt--`；当 `ref_cnt == 0`，块回收入空闲池。
- **示例**：

  - 块大小 $B=2$，prompt `"The cat sat"` (长度 3) 使用块#5 (`The cat`) 和块#9 (`sat`)。
  - 请求 A (`"The cat sat"`) ：页表 [5, 9]。
  - 请求 B (`"The cat slept"`)：共享前缀 `"The cat"`，页表 [5, 12] (12为新块)。
  - 节省一个物理块；波束宽度 $k=4$ 时节省更显著。
- **补充：写时复制 (Copy-on-Write)**

  - 当出现需要修改共享块的场景（如高级提示微调），vLLM 支持 **写时复制**：复制原块内容到新块，修改新块，`ref_cnt` 分别调整，保证隔离。
  - 常规自回归生成 **仅追加、不修改**，所以不触发复制，零开销共享。

> **→ 物理块池终究是有限的，当并发请求耗尽显存时，必须引入抢占机制。**

---

### 第四层：抢占与交换 — 动态腾挪

- **问题：物理块池耗尽**

  - 等待队列中的请求无法获得必需的 KV 块，必须让渡资源。
- **抢占策略**

  - **交换（Swapping）**

    - 将某个序列的全部物理块内容从 **GPU 显存拷贝到 CPU 内存**，释放 GPU 块。
    - 恢复时再拷回，开销受 PCIe 带宽限制。
    - 类比：操作系统将进程内存页换出到磁盘交换区。
  - **重计算（Recomputation）**

    - 直接丢弃被抢占序列的所有 KV 块，但保留 **输入 token 序列**。
    - 重新调度时，将 token 串重新送过模型，**重算** 全部 $K,V$，重建 KV Cache。
    - 开销为计算量，无数据搬运。
  - vLLM 调度器根据序列长度、剩余生成长度等动态选择代价更低的方案。
- **效果**：显存超量时仍可保持高吞吐，避免因内存拒绝请求。

> **→ 内存可动态回收和再分配，使得批次构成可以在每一步推理时灵活变化——这便是连续批处理的基础。**

---

### 第五层：连续批处理 (Continuous Batching)

- **旧问题：静态批处理造成队头阻塞**

  - 传统服务系统将请求打包成批次，必须等待 **批次中所有请求** 生成结束才返回结果。
  - 短请求被长请求阻塞，GPU 利用率呈锯齿状，时延高。
- **vLLM 的解决：迭代级动态调度**

  - 每次模型前向传播（一个 step）前，调度器执行：

    1. 检查已完成的请求（生成 EOS 或达到最大长度），释放其所有物理块（`ref_cnt--`）。
    2. 从等待队列拉取新请求，尝试分配第一个逻辑块。
    3. 将当前所有活跃请求组成新 batch，执行下一 step。
  - 因为 KV Cache 是按块动态分配的，**请求随时加入或退出不会破坏其他序列的缓存**。
- **结果**：完全消除队头阻塞，GPU 持续满载，吞吐量提升数倍，同时 P99 延迟大幅下降。

---

### 核心原理链总结

```text
KV Cache 固定分配 → 内部碎片
      ↓ (分页)
PagedAttention (逻辑块/物理块/页表) → 按需分配，零碎片
      ↓ (页表可重映射)
块共享 + 引用计数 → 消除前缀冗余
      ↓ (池耗尽)
抢占 (交换/重计算) → 显存超限依然平稳服务
      ↓ (动态释放/分配)
连续批处理 → 消除队头阻塞，极致吞吐
```

**vLLM 的本质**：将操作系统成熟的内存管理哲学（虚拟内存、分页、写时复制、交换）成功移植到大模型推理领域，实现了一个 **面向 KV Cache 的虚拟存储系统**。
