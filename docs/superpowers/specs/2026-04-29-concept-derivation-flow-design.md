# 概念推导层级展开流程 — 设计文档

> 本设计是对 `design.md`（问题驱动推导学习）的补充，聚焦于「概念→子概念」的层级展开流程。
> 回答的核心问题：用户如何从一个概念自然地过渡到其子概念的推导？
>
> 关键约束：用户首次进入概念时对该概念的「过程」是未知的。
> 核心方法：先给出骨架流程和引导问题 → 用户填写对应的概念 → 用户提问补充不理解的点。

---

## 1. 核心理念

```
┌─────────────────────────────────────────────┐
│  认知循环 N（当前概念）                        │
│                                              │
│  过程 → 矛盾 → 问题 → 推导 → 揭晓概念          │
│                                              │
│  揭晓 → 子概念骨架 → 子概念问题 → 填写 → ...   │
└─────────────────────────────────────────────┘
```

首次进入概念画板时，不展示空白画板。而是展示一个**预置的骨架流程**——包含已知的前置节点、带问题的空缺节点、和当前概念节点。用户的任务是：**把候选概念拖入空缺节点，或在空缺处创建新概念**。

---

## 2. 骨架画板：首次进入的填充式推导

### 2.1 画板初始状态

```
┌────────────────────────────────────────────────────┐
│  vLLM  ·  过程梳理画板                                │
│                                                      │
│  ┌──────┐    ┌──────┐    ┌──────┐    ┌──────┐     │
│  │      │    │ ❓   │    │ ❓   │    │      │     │
│  │ 配?  │──→│ 设备?│──→│ 数据?│──→│ 运行?│     │
│  │      │    │      │    │      │    │      │     │
│  └──────┘    └──────┘    └──────┘    └──────┘     │
│     ↑           ↑           ↑           ↑          │
│  配置了    初始化在   数据怎么   谁负责               │
│  什么？    什么硬件？  表示？     执行？              │
│                                                      │
│  ┌─ 候选概念区 ───────────────────────────┐         │
│  │                                         │         │
│  │  拖动概念到空缺节点：                      │         │
│  │  [VllmConfig] [Device] [Tensor]         │         │
│  │  [ModelRunner] [ModelLoader] [+ 自定义] │         │
│  │                                         │         │
│  └─────────────────────────────────────────┘         │
│                                                      │
│  [💬 提问]           [提交梳理]   4空缺 · 0已填      │
└──────────────────────────────────────────────────────┘
```

### 2.2 流程说明

| 要素 | 说明 |
|------|------|
| 绿色节点 | 已知前置概念（预置在画布上） |
| ？空缺节点 | 待填充的流程步骤，每个带一个引导问题 |
| 蓝色节点 | 当前概念（高亮） |
| 候选概念区 | 可拖入空缺节点的候选概念 + 自定义入口 |
| 提问按钮 | 用户随时可以提问 |

### 2.3 空缺节点的引导问题

每个空缺节点展示一个**问题**，而不是概念名。问题帮助用户思考「这里需要什么」：

```
空缺 1：「要让 LLM 跑推理，第一步需要知道模型的什么？」
→ 正确答案：VllmConfig

空缺 2：「配置好了，代码要在什么硬件上执行？」
→ 正确答案：Device

空缺 3：「模型权重和中间结果用什么数据结构表示？」
→ 正确答案：Tensor

空缺 4：「谁负责驱动模型的前向计算过程？」
→ 正确答案：ModelRunner
```

问题从 `ProcessChain.steps[].question` 或动态生成的 `BaseQuestion` 中读取。

### 2.4 填充交互

用户有两种方式填充空缺：

**方式 A：拖拽候选概念**
```
候选概念区 [VllmConfig] ──拖拽──→ 空缺 1
→ 空缺被填上，显示 VllmConfig
→ 如果填对了：绿色对勾反馈
→ 如果填错了：红色提示「这个概念的职责不太匹配哦」
```

**方式 B：创建自定义节点**
```
用户点击空缺 →「没有匹配的概念？创建一个」
→ 输入名称 → 新概念自动关联当前概念
```

### 2.5 提交与验证

用户填充完后点击「提交梳理」：

```
→ 系统比对各空缺的填充结果
→ 正确/错误逐项展示
→ 未填充的空缺标记为 gap

┌─ 提交结果 ──────────────────────────┐
│                                      │
│  ✓ VllmConfig   正确                  │
│  ✓ Device       正确                  │
│  ⚡ Tensor      错误 → 正确是 GpuAllocator
│  ⚡ 空缺 4      未填充 → [去查看]      │
│                                      │
│  填写率: 75%                          │
│                                      │
│  [对照验证详情 → ComparisonPanel]     │
└──────────────────────────────────────┘
```

提交后跳转到 ComparisonPanel（与 `design.md` §4 一致）。

### 2.6 与 design.md 现有画板的关系

骨架画板**替代**`design.md` §3 中「空白画板」作为首次进入状态。用户一旦开始自由拖拽/连线（即对骨架做了修改），骨架模式自动退出，进入自由模式。

| 状态 | 画板表现 |
|------|----------|
| 首次进入（未提交过） | 骨架画板（空缺节点 + 引导问题） |
| 骨架提交后 | 自由画板（可拖拽、连线、自定义） |
| 后续重新进入 | 自由画板（恢复上次保存状态） |

## 3. 提问机制：问题驱动知识生长

### 3.1 提问入口

用户随时可以点击 💬 提问按钮：

```
用户输入：「CacheConfig 和 ModelConfig 有什么区别？」

→ 问题保存到该概念的问题集
→ 记录提问时的上下文（步骤、位置）
```

### 3.2 问题的三种去向

```
                    ┌─ 留在问题集（供复习回顾）
  用户提问 ─────→  ├─ 转换为新概念（创建图谱节点）
                    └─ 补充到骨架流程（成为新的空缺/步骤）
```

**留在问题集**：默认行为。问题出现在问题列表中，可被查看和回答。

**转换为新概念**：当问题指向一个未建模的子领域时：

```
提问：「VllmConfig 的配置项是怎么组织起来的？」

如果系统或用户发现这个问题指向一个新子概念：
→ 「这个问题指向一个新的子概念，要创建吗？」
→ 用户确认 → 创建 Concept 节点
→ 新概念自动关联到当前概念
→ 新概念出现在图谱中
```

**补充到骨架流程**：当问题揭示了一个遗漏的流程步骤：

```
用户填充时发现缺少「配置校验」这一步：
→ 提问：「VllmConfig 加载后会不会做配置校验？」

→ 「要添加'配置校验'为流程步骤吗？」
→ 用户确认 → 补充到 ProcessChain.steps
→ 下次进入骨架画板时会显示这个新空缺
```

### 3.3 问题集数据

```typescript
interface ConceptQuestion {
  id: string
  conceptId: string
  question: string
  context: {
    location: 'skeleton' | 'canvas' | 'comparison'
    stepId?: string
  }
  status: 'open' | 'converted_to_concept' | 'converted_to_step' | 'resolved'
  convertedTo?: {
    type: 'concept' | 'step'
    targetId: string
  }
}
```

## 4. 子概念过渡

当用户点击 ComparisonPanel 中的 gap 或关联上下文中的概念时：

| 入口 | 子概念状态 | 跳转目标 |
|------|-----------|----------|
| gap 点击 | 首次进入 | 骨架画板（带父上下文问题） |
| 关联上下文点击 | 首次进入 | 骨架画板 |
| 图谱双击 | 首次进入 | 骨架画板 |
| 任意入口 | 已进入过 | 自由画板（恢复状态） |

进入子概念骨架画板时，空缺节点会携带来自父概念的上下文：

```
空缺 1：「来自父概念 vLLM：配置好了，模型要在什么硬件上执行？」
→ 正确答案：Device
```
