KV-BLOCK-MEMORY(7)            vLLM 存储计算           KV-BLOCK-MEMORY(7)

NAME
  2×L×H×d×B×sizeof(dtype) — 物理块占用显存的精确推导

SYNOPSIS
  块内存量 = 2 × L × H × d × B × sizeof(dtype)

DESCRIPTION
  该公式量化了 vLLM PagedAttention 中一个物理 cache block 在 GPU
  显存中占据的字节数。它以因子形式拆解自回归模型生成过程中必需存留
  的键/值(K/V)张量的总规模。

  ● 问题 1：物理块内究竟存储了什么，使得单块内存量如此计算？
    ├─ 子概念：物理块是 K/V 缓存的连续存储单元
    │  • 为 B 个连续的 token 保存其在所有 transformer 层、所有
    │    注意力头的 K 和 V 数值。
    │  • 块内数据布局：(B, L, 2, H, d) —— 先 token，再层，再 K/V
    │    分离，再头划分，最后向量维度，实际布局由内核决定。
    ├─ 解决过程：逐因子展开
    │  1. B : 块容纳的 token 数，是分块粒度的基本变量。单块必须为
    │     这 B 个 token 各存储完整的 K 和 V，故乘数 B 出现。
    │  2. L : 模型总层数。自回归推理时，每一层都要对其输入序列计算
    │     注意力，因此每层都维护独立的 KV 缓存，块必须包含所有 L 层
    │     的 K/V。
    │  3. H : 注意力头总数（或等效头数）。多头注意力将向量空间拆分为
    │     H 个独立子空间，每个头的 K、V 分别存储。即便使用分组查询
    │     (GQA)，仍按最大头数分配以维持块表简单性，故此因子为 H。
    │  4. d : 每个注意力头的向量维度（head_dim）。一个 token 在一个
    │     头中的一个矩阵（K 或 V）为形状 [1, d] 的向量，其大小正比
    │     于 d。
    │  5. 2 : 每个 token 在每个头中同时需要 K 和 V 两个张量。
    │  6. sizeof(dtype) : 存储精度对应的单元素字节数（fp16/bf16
    │     为 2，fp8 为 1）。
    │  组合即为总字节数。
    └─ 引出问题 2：为什么乘积如此精确？内部是否还有隐藏开销？

  ● 问题 2：上述乘积之外，是否有对齐填充或其他元数据？
    ├─ 子概念：对齐与最小分配单元
    │  GPU 内存分配常对齐到 512 或 256 字节边界，实际占用可能略大
    │  于公式值，但公式给出的是严格存储有效载荷所需的字节数，用作
    │  容量规划与调度决策的依据。
    ├─ 解决过程：
    │  1. 有效载荷 = B × L × H × d × 2 × sizeof(dtype)
    │  2. 对齐开销可忽略于逻辑推导，但调度器在计算空闲块数时会将
    │     对齐后的块大小纳入考量，即 (有效载荷 + 对齐填充) 为物理
    │     上真实的块尺寸。
    └─ 引出问题 3：给定设备显存总量，如何快速估算可并发管理的
       物理块与序列数？

  ● 问题 3：由块内存公式到系统并行规模的反推
    ├─ 子概念：最大物理块数与最大并发序列数
    │  设显存总量为 M_total，其中模型权重占 M_model，其他开销 M_others。
    │  可用于 KV 缓存的显存 M_kv = M_total - M_model - M_others。
    │  最大物理块数 N_blocks_max = ⌊M_kv / (块内存量)⌋。
    │  对于长度上限 L_max 的序列，所需块数 n = ceil(L_max / B)。
    └─ 解决过程：
      1. 最大并发序列数 S_max ≈ ⌊N_blocks_max / n⌋ （假设无边共享）。
      2. 若开启前缀缓存，实际并发数可因共享前缀而显著提高。
      衍生公式： 单块内存 = 2LBHd × sizeof(dtype)
                 其中 B 和 d 为架构决定，L、H 为模型超参。
      以上构成 vLLM 调度器内存核算的基石。
