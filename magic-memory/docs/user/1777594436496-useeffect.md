```text
NAME
  useEffect — 在 React 函数组件中协调副作用与声明式渲染的基石 Hook

SYNOPSIS
  useEffect(effect: EffectCallback, deps?: DependencyList): void;

  type EffectCallback = () => (void | Destructor);
  type Destructor    = () => void;
  type DependencyList = ReadonlyArray<unknown>;

DESCRIPTION
  问题 0: 函数组件 UI = render(props, state) 必须是纯函数，但网络请求、订阅、DOM 焦点等副作用必须存在。
    解决: 将副作用声明为“效果”（Effect），从渲染流程中分离。
      子概念: Effect = 需在提交阶段（commit phase）之后执行的过程。
      过程:
        1. 组件渲染时调用 useEffect，将 effect 闭包及依赖存入 Fiber 节点。
        2. React 在将 DOM 变更绘制到屏幕后，调度 effect 执行。
      公式:
        render:    vdom = component(props, state)
        commit:    commitRoot() → flushPassiveEffects() → effect()
    引出问题 1: 每次提交都执行所有 effect 会造成性能浪费，如何按需执行？

  问题 1: 如何避免不必要的重复执行？
    解决: 引入依赖数组 deps，在两次提交之间做浅比较。
      子概念: 依赖项 (DependencyList) — effect 读取的、可能随时间变化的响应式值集合。
      过程:
        - 当 deps === undefined 时，每次提交后都重新执行 effect。
        - 当 deps 为数组时，用 Object.is() 逐项比较 nextDeps[i] 与 prevDeps[i]。
        - 若全等，跳过执行。
      公式:
        shouldReinvoke =
          prevDeps === undefined
            ? true
            : !areHookInputsEqual(nextDeps, prevDeps)
      引出问题 2: 副作用通常会申请外部资源（定时器、订阅），如何保证这些资源被正确释放？

  问题 2: 如何安全释放副作用申请的资源，避免内存泄漏或状态错误？
    解决: effect 函数可返回一个“清理函数”（Destructor）。
      子概念: 清理函数 (cleanup) — 释放前一次 effect 资源的逆向操作。
      过程:
        1. 执行当前 effect 前，若 prevEffect.cleanup 存在，先调用它。
        2. 组件卸载前，调用最后一次 effect 的 cleanup。
      公式:
        重执行流程: cleanup_prev() → effect_curr() → (产生 cleanup_curr)
        卸载流程:   cleanup_last()
      引出问题 3: 若 deps 未包含 effect 内用到的所有响应式值，会出现“闭包过期”问题。

  问题 3: 为何 effect 内读取的 props/state 可能是旧值？（闭包陷阱）
    原因: 每次渲染产生独立作用域，useEffect 捕获当次渲染的 props_i 与 state_i。
      公式:
        effect_i ← closure( props_i, state_i )
        若 deps 不全 → effect_i 永不更新 → 观察到 stale values
    解决: 确保 deps 包含所有在 effect 中读取的、可能随时间变化的变量。
      辅助规则: eslint-plugin-react-hooks 的 exhaustive-deps 规则静态分析闭包依赖。
      引出问题 4: 有时刻意不想添加某个依赖（如频繁变化的 callback），有无绕过闭包的方式？

  问题 4: 如何在不添加依赖的情况下，在 effect 中访问最新值？
    解决: 使用可变容器 useRef 保持最新值引用。
      子概念: Ref 为逃逸舱，其 .current 可变，且在所有渲染周期共享同一对象。
      公式:
        const latest = useRef(prop);
        latest.current = prop;        // 渲染阶段同步刷新
        useEffect(() => {
          const currentProp = latest.current; // 总是最新
        }, [/* 其他依赖 */]);
      引出问题 5: 所有 effect 都在浏览器绘制之后异步执行，若需要同步修改 DOM、避免闪烁该怎么办？

  问题 5: 有些副作用必须在浏览器绘制前同步执行（如测量布局），怎么办？
    解决: 使用 useLayoutEffect —— 签名完全相同，但执行时机不同。
      过程:
        - useLayoutEffect 在 commit 阶段同步刷新，在浏览器绘制之前运行。
        - useEffect    在绘制之后异步调度（通过 Scheduler/MessageChannel）。
      时机对比:
        render → commit → useLayoutEffect (同步) → 浏览器绘制 → useEffect (异步)
      公式:
        passiveEffect (useEffect)   → 调度为 NormalPriority
        layoutEffect (useLayoutEffect) → 同步 callImmediately

  总结核心机制:
    React 维护函数组件对应的 Fiber.updateQueue，其中持有 effect 链表。
    类型:
      type Effect = {
        tag: HookFlags,          // HasEffect | Passive
        create: EffectCallback,
        destroy: Destructor | void,
        deps: DependencyList | void,
        next: Effect | null,
      };
    生命周期:
      挂载:   invokeGuardedCallback → create() → destroy 存入链表
      更新:   areHookInputsEqual 决定是否执行 destroy_prev → create
      卸载:   执行 destroy_curr

SEE ALSO
```
